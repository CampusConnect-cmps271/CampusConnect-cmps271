## Environment file and GitHub

Keep `frontend/.env` local. It contains these entries, initially blank:

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
```

Fill them using the project's **Connect** dialog. The helpers expect the new
`sb_publishable_...` key. Project URLs and publishable keys are designed to be visible
in browser applications; placing them in `.env` does not make browser values secret.
Secret/service-role keys must never be placed in `NEXT_PUBLIC_` variables.

Git ignore rules protect local configuration from normal `git add` commands.
The blank `.env.example` template and source files can be committed. No Git staging,
commits, pushes, GitHub configuration changes, or Jira changes were performed.

## How to run and connect

1. Fill in `frontend/.env` with your own Supabase Project URL and publishable key.
2. From the repository root, run:

   ```bash
   cd frontend
   npm run dev
   ```

3. Open <http://localhost:3000> and click **Check connection**.
4. Restart the development server after changing `.env`. If you created `.env.local`
   earlier, remove conflicting values there because Next.js gives it priority.

For production, set the values before building. `NEXT_PUBLIC_` values are embedded
at build time, so changing them requires running `npm run build` again.

On a fresh clone, copy `.env.example` to `.env` and run `npm ci` before `npm run dev`.
Use Node.js 22 or newer.

A successful check means Supabase Auth accepts the connection details. It does not
verify email delivery, registration behavior, RLS policies, database access, or role rules.
Your actual cloud project has not been tested because its URL/key were not supplied.
No users, tables, authentication hooks, or cloud settings were created or changed.
